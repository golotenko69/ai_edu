# ИИ-наставник: универсальный ИИ-агент по программированию

Универсальный ИИ-агент для вузов и колледжей с локальными моделями. Это не только задачник: агент работает с проектами как агент-разработчик — читает файлы, запускает программы, ищет ошибки, пишет и правит код. При этом его полномочия задаёт преподаватель.

Два способа работы:

1. **Свободный агент** (`/agent`) — для любых задач и проектов, у всех ролей.
   - **Преподаватель и администратор** работают с агентом без ограничений и сами выбирают режим для каждого проекта.
   - **Студент** получает агента в режиме, который задал преподаватель. По умолчанию это «Объяснение»: агент разбирает код и объясняет, но не пишет готовые решения.
2. **Учебные задания** (`/student`, `/teacher`) — агент по правилам задания, проверка понимания, запись сессий, живая пара, контрольные, отчёты.

| Режим свободного агента | Что может агент |
|---|---|
| 01 · Объяснение | читает проект, запускает код, объясняет, делает ревью; файлы не меняет, готовый код не пишет |
| 02 · Подсказки | то же, но ведёт наводящими вопросами |
| 03 · Агент | полный режим: создаёт и правит файлы, запускает, отлаживает, доводит задачу до конца |

Инструменты агента: `list_files`, `read_file`, `search`, `run_file`; в режиме «Агент» добавляются `write_file`, `replace_in_file` и `delete_file`. Агент вызывает их через стандартный tool calling (Ollama, LM Studio, vLLM). Если модель его не поддерживает, агент переходит на текстовый протокол. Режим проверяется на сервере: в ограниченных режимах инструменты записи модели просто недоступны, а готовый код в ответе скрывается проверкой.

Всё работает на одном ПК: как десктопное приложение, в Docker или напрямую на Python 3.10+. Нужна только стандартная библиотека Python. Редактор Monaco и шрифты лежат в `web/vendor`, поэтому интерфейс работает без интернета. Без модели платформа работает в демо-режиме, локальную модель подключают в настройках.

## Десктопная версия

```bash
install_desktop.bat
```

Скрипт создаёт ярлык «ИИ-наставник» на рабочем столе и в меню «Пуск». Ярлык открывает платформу отдельным окном приложения (Edge или Chrome в режиме `--app`, со своим профилем). Если платформа уже запущена в Docker на порту 8000, окно подключается к ней. Если нет, лаунчер сам поднимает сервер и останавливает его, когда окно закрыто. Лог лаунчера пишется в `data/desktop.log`.

## Запуск из консоли

```bash
python run.py
```

Или двойной щелчок по `start.bat`. После запуска откройте http://localhost:8000.

| Роль | Логин | Пароль |
|---|---|---|
| Преподаватель | `teacher` | `teacher` |
| Студенты группы ИВТ-21 | `student1` … `student4` | `student` |
| Администратор | `admin` | `admin` |

Вход привязан к вкладке браузера: в одной вкладке можно работать студентом, в соседней — преподавателем и смотреть, как всё обновляется вживую.

## Запуск в Docker

В образе есть Python и g++, поэтому задания на C++ работают без установки компилятора. Код студентов выполняется внутри контейнера под непривилегированным пользователем, с лимитами памяти, CPU и числа процессов. База хранится в томе `aiedu-data` и переживает перезапуски.

**Только платформа** (модель — Ollama/LM Studio на этом же ПК):
```bash
docker compose up -d
```
Откройте http://localhost:8000. Или двойной щелчок по `docker_start.bat`. Из контейнера модель на хосте видна по адресу `host.docker.internal`: кнопка «Ollama» в настройках подставляет его сама.

**Платформа + Ollama + модель** — всё в контейнерах:
```bash
docker compose -f docker-compose.yml -f docker-compose.ollama.yml up -d
```
Модель `qwen2.5-coder:7b` скачается автоматически при первом запуске (около 5 ГБ). Другую модель можно задать так:
```bash
AIEDU_LLM_MODEL=qwen2.5-coder:14b docker compose -f docker-compose.yml -f docker-compose.ollama.yml up -d
```
Для видеокарты NVIDIA раскомментируйте блок `deploy` в `docker-compose.ollama.yml`.

**Переменные окружения** (необязательные; настройки из панели преподавателя важнее):

| Переменная | Назначение |
|---|---|
| `AIEDU_PORT` | порт на хосте (по умолчанию 8000) |
| `AIEDU_LLM_PROVIDER` | `openai` или `mock` |
| `AIEDU_LLM_BASE_URL` | адрес OpenAI-совместимого API |
| `AIEDU_LLM_MODEL` | модель для ответов студенту |
| `AIEDU_CHECKER_MODEL` | отдельная модель-контролёр |
| `AIEDU_LLM_API_KEY` | ключ, если сервер модели его требует |

**Публикация в Docker Hub** (собирает образ под amd64 и arm64):
```bash
docker_publish.bat ВАШ_ЛОГИН
```
На Linux/macOS: `./docker_publish.sh ВАШ_ЛОГИН`. После этого на любом ПК:
```bash
docker run -d -p 8000:8000 -v aiedu-data:/app/data --add-host host.docker.internal:host-gateway ВАШ_ЛОГИН/ai-nastavnik
```

Сбросить демо-данные:
```bash
docker compose down -v
```

## Подключение локальной модели

**Ollama** (проще всего):
1. Установите Ollama с ollama.com.
2. Скачайте модель для кода:
   ```bash
   ollama pull qwen2.5-coder:7b
   ```
3. В панели преподавателя откройте «Модели и настройки», выберите провайдера «Локальная или облачная модель», нажмите «Ollama» → «Загрузить список» → «Проверить связь» → «Сохранить».

**LM Studio / llama.cpp / vLLM**: то же самое, кнопки быстрой настройки подставляют стандартные адреса (`:1234`, `:8080`, `:8000`). Подойдёт любой сервер с OpenAI-совместимым API `/v1/chat/completions`, включая облачные; для них есть поле API-ключа.

Модели можно разделить:
- сильная модель отвечает студенту;
- лёгкая модель-контролёр проверяет ответы агента, задаёт вопросы на понимание и оценивает объяснения студентов.

Рекомендации по моделям: `qwen2.5-coder:7b` или `14b` для ответов, `qwen2.5:3b` для контролёра. Модели-«размышлялки» (DeepSeek-R1, Qwen3) тоже подходят: блок `<think>` вырезается.

## Что реализовано

**Студент** (`/student`)
- Редактор Monaco с подсветкой; Python и C++ (для C++ нужен g++/clang++ в PATH или Docker).
- Запуск со своим вводом, автотесты (открытые и скрытые), сдача работы.
- Панель агента рядом с кодом и кнопка «Объяснить ошибку» последнего запуска.
- Вставка кода агента — только с подтверждением. Вставленные строки подсвечиваются фиолетовым и остаются помеченными при правке. Код, скопированный из чата вручную, распознаётся и тоже помечается.
- Проверка понимания после вставки: обязательная (редактор блокируется до ответа) или мягкая. Вопрос может задать и преподаватель прямо во время пары.
- Контрольный режим: ожидание старта, полноэкранный режим, запись ухода из окна, блокировка внешних вставок, автосдача при завершении.

**Агент** (`server/agent.py`) — слой логики вокруг модели
1. Пять режимов: Молчание, Объяснение, Подсказки, Фрагменты, Свободный.
2. Правила преподавателя поверх режима:
   - запрещённые конструкции и функции;
   - лимит обращений;
   - максимальный размер фрагмента;
   - эталонное решение;
   - материалы курса.
3. Сборка контекста: задание, правила, материалы, текущий код, история диалога.
4. Отдельная проверка каждого ответа:
   - запрещённые конструкции — разбором кода (AST), а не моделью;
   - размер кода в ответе по режиму;
   - **готовое решение**: код агента прогоняется на тестах задания, и если проходит все — это решение;
   - модель-контролёр.

   При нарушении ответ сначала переписывается, а если не помогло — код из него вырезается.
5. Распознавание попыток обхода («игнорируй инструкции», «я преподаватель», «срочно, отчислят»…) с записью в журнал.

**Преподаватель** (`/teacher`)
- **Курсы и задания**: условие, заготовка, тесты, режим и правила агента, эталон с проверкой на тестах, «Проверка защиты агента» (три попытки выпросить решение).
- **Живая пара**: статус каждого студента, переключение режима для всей группы или одного студента, доля кода агента, проверки понимания, метки риска, вопрос студенту, запуск и завершение контрольной.
- **Просмотр сессии**: ползунок «как писался код» по версиям с подсветкой строк агента, полный журнал (диалог, заблокированные ответы с оригиналом, запуски, вставки, проверки), выставление оценки.
- **Отчёты**: матрица «студенты × задания», сводка по группе, выгрузка оценок в CSV (Excel/Moodle).
- **Группы**: импорт студентов списком.
- **Настройки**: модели и запуск кода.

## Чем прототип отличается от целевой архитектуры

| В документе | В прототипе | Почему |
|---|---|---|
| Клиент на VSCodium / Theia | Веб-клиент с Monaco (тот же движок, что в VS Code) | Работает без установки на любом ПК класса. API клиента готов к замене на расширение |
| PostgreSQL, ClickHouse | SQLite, журнал событий в отдельной таблице | Ноль зависимостей; схема переносится один к одному |
| Docker-контейнеры для кода | Отдельный процесс с тайм-аутом; Docker включается в настройках | Docker есть не везде. **Без Docker код студента не изолирован**, это нормально только для локальной работы |
| Режим киоска ОС | Полноэкранный браузер + запись ухода из окна; `kiosk_client.bat` запускает Edge в киоске | Настоящая блокировка ОС требует групповых политик Windows или отдельной Linux-сессии |
| LDAP / AD, Moodle | Локальные учётки, импорт списком, CSV-выгрузка | Интеграции — этап масштабирования |
| GigaChat / YandexGPT | OpenAI-совместимый адаптер | Для GigaChat (OAuth) и YandexGPT нужен свой класс в `server/llm.py` рядом с `openai` |

## Работа в компьютерном классе

1. На ПК преподавателя или сервере: `start_class_server.bat` (сервер слушает сеть).
2. На ПК студентов:
   ```bash
   kiosk_client.bat http://IP-сервера:8000
   ```
   Это Edge в режиме киоска.
3. Откройте порт 8000 в брандмауэре Windows.

## Структура

```
run.py              точка входа (--host, --port)
server/app.py       HTTP-сервер и REST API
server/agent.py     агент учебных заданий: режимы, промпты, проверка ответов, понимание, метки риска
server/workspace.py универсальный агент: проекты, инструменты, цикл tool calling, политики режимов
server/llm.py       адаптер моделей (openai-совместимый + демо)
server/analysis.py  разбор кода: запрещённые конструкции, извлечение кода из ответа
server/runner.py    запуск кода и тесты
server/db.py        SQLite-схема
server/seed.py      демо-курс, 7 заданий во всех режимах
web/                клиент студента, панель преподавателя, Monaco, шрифты
desktop/            десктопная версия: лаунчер, иконка, установка ярлыка
Dockerfile, docker-compose*.yml, docker_*.bat|sh   запуск и публикация в Docker
data/               база SQLite, проекты агента (data/workspaces), профиль десктоп-окна
```
